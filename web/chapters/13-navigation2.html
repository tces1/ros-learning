第 13 章　Navigation2（Nav2）导航

让机器人自己走到目标点：先用 SLAM 建出地图，再用 AMCL 在地图中定位，最后由 Nav2 规划路径、躲避障碍、执行运动。本章基于第 9 章的仿真小车完成全流程，并用 Python 实现多航点巡逻。

动手约 4–5 小时移动机器人核心

本章目标

  • 理解 Nav2 的整体架构与各服务器的职责
  • 用 slam_toolbox 建图并保存
  • 用 AMCL 在已知地图中定位
  • 理解代价地图的分层与关键参数
  • 理解行为树如何编排导航流程
  • 用 Simple Commander API 编程控制导航

13.1 导航需要什么

问题谁来回答输入 → 输出
环境长什么样？SLAM（slam_toolbox）或地图服务器激光 + 里程计 → /map
我在哪？AMCL（或 SLAM 本身）地图 + 激光 + 里程计 → map→odom TF
怎么走过去？Planner Server（全局规划）地图 + 起点 + 终点 → 路径
当下怎么动？Controller Server（局部控制）路径 + 局部障碍 → /cmd_vel
卡住了怎么办？Behavior Server（恢复行为）原地旋转、后退、等待、清除代价地图
以上如何协调？BT Navigator（行为树）目标 → 调用上述服务器

先跑官方示例建立直观认识

ros2 launch nav2_bringup tb3_simulation_launch.py headless:=False 会启动 TurtleBot3 仿真 + 完整 Nav2。在 RViz 点「2D Pose Estimate」给初始位置，再点「Nav2 Goal」给目标，观察机器人规划并移动。

13.3 第一步：SLAM 建图

启动第 9 章的仿真（使用 Gazebo DiffDrive 插件的版本，它发布 /cmd_vel(Twist)、/odom、/scan，与 Nav2 默认配置一致）：

RViz 中 Fixed Frame 改为 map，添加 Map 显示（Topic /map），可以看到地图随着行驶逐步生成。

建图技巧
  • 速度放慢（线速度 0.2 m/s 以下，转弯更慢），里程计误差越小地图越准。
  • 最后回到起点附近，让 SLAM 检测到「回环」并修正累计误差。
  • 避免长时间面对空旷区域或玻璃，激光特征少会导致匹配失败。

保存地图

地图图片可以用 GIMP 等工具手动编辑，例如涂黑不希望机器人进入的区域（更规范的做法是使用 Keepout 过滤器）。

13.4 第二步：定位与导航

关闭 SLAM 和 teleop，保持仿真运行，启动 Nav2：

  1. RViz 工具栏点 2D Pose Estimate，在地图上机器人实际位置处点击并拖出朝向。AMCL 粒子云（绿色箭头）会收敛。
  2. 点 Nav2 Goal，在目标处点击并拖出朝向，机器人开始导航。
  3. 观察：绿色线是全局路径，局部代价地图中障碍物周围有彩色膨胀区。
边建图边导航

也可以不保存地图：同时运行 slam_toolbox 和 ros2 launch nav2_bringup navigation_launch.py use_sim_time:=true（不含 AMCL 和地图服务器，定位由 SLAM 提供）。适合探索未知环境。

13.5 参数文件

先把官方默认参数复制到自己的包中再修改：

下面是需要根据机器人修改的关键部分（节选）：

robot_radius 与 footprint

my_bot 车身 0.4 × 0.3 m，外接圆半径 = √(0.2² + 0.15²) ≈ 0.25 m，再留一点余量取 0.26。对于长方形机器人，用 footprint: "[[0.22, 0.17], [0.22, -0.17], [-0.22, -0.17], [-0.22, 0.17]]" 更精确，可以通过更窄的通道。

13.6 代价地图详解

代价地图把世界划分为栅格，每格一个 0–255 的代价值：

代价含义
0空闲
1–252靠近障碍物，越大越危险（膨胀层产生）
253内切：机器人中心在此必然碰撞
254致命：障碍物本身
255未知
层作用
StaticLayer来自 /map 的静态障碍
ObstacleLayer来自激光的实时障碍（2D），可标记与清除
VoxelLayer来自点云 / 深度相机的 3D 障碍，投影到 2D
InflationLayer在障碍周围按距离指数衰减地增加代价
KeepoutFilter / SpeedFilter禁行区、限速区（配合掩膜地图）

inflation_radius 决定机器人离墙多远就开始「感到不适」，cost_scaling_factor 越大代价衰减越快（越敢贴墙）。机器人总在走廊中间画龙或过不了门，多半要调这两个参数。

13.7 规划器与控制器选择

插件类型适用
NavFn规划器经典 Dijkstra / A*，简单可靠
Smac 2D规划器2D A*，路径更平滑，推荐圆形差速机器人
Smac Hybrid-A*规划器考虑最小转弯半径，适合阿克曼（汽车式）底盘
Smac State Lattice规划器任意运动学约束、非圆形机器人
Theta*规划器任意角度直线路径
Regulated Pure Pursuit控制器跟踪路径，参数直观，适合初学和服务机器人
DWB控制器动态窗口法，可调评分项多
MPPI控制器模型预测，效果最好但计算量大
Graceful Controller控制器平滑接近目标位姿

13.8 行为树

BT Navigator 使用 BehaviorTree.CPP 的 XML 行为树。默认树的简化版本如下：

节点类型行为
Sequence / PipelineSequence按顺序执行子节点，全部成功才成功
Fallback / ReactiveFallback依次尝试子节点，一个成功即成功
RecoveryNode第一个子节点失败时执行第二个（恢复），然后重试
RateController限制子节点执行频率
动作节点ComputePathToPose、FollowPath、Spin 等，调用对应服务器

可在参数 bt_navigator.default_nav_to_pose_bt_xml 中指定自定义行为树，例如加入「电量低则先去充电」的逻辑。用 Groot2 可以图形化编辑和实时监视行为树。

13.9 用 Python 编程导航

nav2_simple_commander 封装了 Nav2 的各种 Action，适合编写上层业务逻辑：

方法作用
goToPose(pose)导航到单个目标
goThroughPoses(poses)经过一系列位姿到达终点（不在中间停留）
followWaypoints(poses)依次到达每个航点（可在每个航点执行任务）
cancelTask()取消当前任务
getPath(start, goal)只规划不执行，用于估算距离
clearAllCostmaps()清除代价地图

13.10 调参与排错

现象可能原因与处理
Nav2 一直不 ReadyAMCL 没有初始位姿（设置 2D Pose Estimate 或 set_initial_pose）；TF 不完整；地图路径错误
“Failed to create plan”目标在障碍物或膨胀区内；起点在致命区（初始位姿错误）；allow_unknown 为 false 且目标在未知区
过不了门 / 窄道减小 inflation_radius 或 robot_radius，改用精确 footprint
在目标附近来回打转放宽 goal checker 的 xy_goal_tolerance / yaw_goal_tolerance
定位漂移、粒子发散里程计质量差；激光与 TF 安装位置不符；AMCL 的 alpha1~alpha5（运动噪声）需调整
代价地图有「幽灵障碍」激光 clearing 未开启；raytrace_max_range 小于 obstacle_max_range
机器人不动但有路径/cmd_vel 没有到达底盘：话题名、Twist / TwistStamped 类型、collision_monitor 是否阻止

测试视角

导航是移动机器人测试工作量最大的部分。Nav2 本身经过大量测试，项目中的问题大多出在参数、地图、传感器配置和场景上，因此测试重点是场景覆盖和参数回归。

维度指标 / 检查
任务到达成功率、用时、路径长度与最短路径之比
精度到点位置误差、朝向误差；定位误差（与真值对比）
安全全程最小障碍距离；是否有急停或碰撞
鲁棒性未知障碍、狭窄通道、动态障碍、不可达目标的行为；恢复行为触发次数
系统生命周期启动是否全部成功；参数文件修改后的回归
参数修改必须回归

调大 inflation_radius 可以让机器人离墙更远，也可能让窄门无法通过；提高控制器速度可以提升效率，也可能让制动距离不够。每次参数修改都应在仿真场景库上重跑并比较成功率，而不是只在一个场景里「看起来更好」。

本章的 BasicNavigator 正是编写场景测试的基础：发送目标、等待、读取结果。把「看着 RViz 判断到没到」变成代码中的判定，就是场景测试的起点。

自测题

1. 为什么局部代价地图使用 odom 坐标系，而全局代价地图使用 map？
局部控制需要平滑连续的坐标，odom 不会跳变；全局规划需要与地图一致的坐标，map 是全局准确的。若局部代价地图用 map，AMCL 修正时障碍物位置会突然跳动，导致控制抖动。
2. SLAM 和 AMCL 能同时运行吗？
不应该。两者都会发布 map→odom 变换，会产生冲突。建图阶段用 SLAM；有了地图后用地图服务器 + AMCL；或者用 slam_toolbox 的 localization 模式替代 AMCL。
3. 行为树中 RecoveryNode 的 number_of_retries=6 是什么意思？
导航子树失败时执行恢复动作然后重试，最多重试 6 次；6 次后仍失败，整个导航任务返回失败。

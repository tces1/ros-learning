10.1 colcon 构建

colcon 是 ROS2 的构建「调度器」：它分析包之间的依赖关系，按拓扑顺序调用每个包自己的构建系统（CMake 或 setuptools）。

命令 / 选项作用
colcon build构建 src 下所有包
--packages-select a b只构建指定的包
--packages-up-to a构建 a 及其所有依赖
--packages-skip a跳过某些包
--symlink-install用符号链接安装 Python 文件、launch、配置，修改后免重新构建
--cmake-args -DCMAKE_BUILD_TYPE=ReleaseRelease 优化编译（性能差距可达数倍）
--cmake-args -DCMAKE_EXPORT_COMPILE_COMMANDS=ON生成 compile_commands.json，供 clangd 补全
--parallel-workers 2限制并行数（内存不足、WSL 卡死时使用）
--event-handlers console_direct+实时显示完整编译输出
--continue-on-error某个包失败后继续构建其他包
永远在工作空间根目录执行 colcon build

在 src 或包目录中执行会在错误的位置生成 build/install，之后 source 的是旧版本，出现「改了代码不生效」的灵异现象。

快速进入包目录

把 source /usr/share/colcon_cd/function/colcon_cd.sh 和 export _colcon_cd_root=~/ros2_ws 加入 ~/.bashrc，之后 colcon_cd my_bot_description 即可跳转。

10.2 package.xml 依赖

标签何时需要
depend编译和运行都要（大多数 ROS 包依赖都用它）
build_depend只在编译时用，如头文件库
exec_depend只在运行时用，如 launch 中启动的其他包、Python 库
test_depend只在测试时用
buildtool_depend构建工具本身：ament_cmake 或 ament_python
依赖声明不全是团队协作中最常见的问题

你的机器上碰巧装了某个库，构建成功；同事的机器上没有，构建失败。所有依赖都必须写进 package.xml，并通过 rosdep 安装来验证。

10.3 rosdep：一键安装依赖

rosdep 读取 package.xml 中的依赖名（称为 rosdep key），把它们翻译成当前系统的 apt / pip 包名并安装。

可用的 key 列表见 rosdistro/rosdep（base.yaml 为系统库，python.yaml 为 Python 库）。

10.4 多仓库管理：vcstool

项目依赖多个 Git 仓库时，用 .repos 文件描述，团队成员一条命令即可拉取全部源码。

10.5 推荐的项目结构

my_bot/                         一个 Git 仓库，多个包
├── my_bot_interfaces/          自定义 msg / srv / action（ament_cmake）
├── my_bot_description/         URDF、mesh、RViz 配置
├── my_bot_gazebo/              仿真世界与仿真 launch
├── my_bot_driver/              硬件驱动（C++）
├── my_bot_navigation/          Nav2 参数、地图
├── my_bot_bringup/             顶层 launch 与参数，不含代码
└── my_bot_apps/                上层业务逻辑（Python）
  • 接口包独立：被所有包依赖，避免循环依赖
  • 算法与 ROS 解耦：核心算法写成不依赖 rclpy/rclcpp 的普通类，节点只负责收发消息并调用它。这样算法可以直接单元测试，也便于移植
  • bringup 只有配置：参数、launch 集中管理，换机器人只需换 bringup

10.10 .gitignore

仓库放哪一层

通常把 src/my_bot 作为一个 Git 仓库，而不是整个 ros2_ws。工作空间是本地构建环境，不应提交。

自测题

1. Python 包使用了 numpy，但没有写进 package.xml，会有什么问题？
在你机器上能运行，但 rosdep install 不会为其他人安装 numpy，部署到新机器或 CI 时运行报 ImportError。应添加 <exec_depend>python3-numpy</exec_depend>。
2. --packages-select 和 --packages-up-to 的区别？
前者只构建列出的包，假设其依赖已构建好；后者会同时构建列出的包及其在工作空间内的全部依赖。首次构建或依赖包有修改时用后者。
3. 为什么建议核心算法不依赖 rclpy？
不依赖 ROS 的纯函数 / 类可以直接用 pytest 测试，无需启动节点、构造消息；也更容易复用在非 ROS 环境（离线分析脚本、其他框架）中。

自查清单

  • 熟悉 --packages-select、--symlink-install、Release 构建
  • 能写出完整的 package.xml 并区分各类依赖标签
  • 在一个干净的工作空间中用 rosdep 成功安装依赖
  • Python 与 C++ 单元测试都能通过 colcon test 运行
  • 项目已放入 Git，并有正确的 .gitignore

11.3 调试 C++ 节点

用调试信息构建

GDB 启动节点

在 launch 中：Node(..., prefix=['xterm -e gdb -ex run --args'])（需安装 xterm）。

常见崩溃原因

  • 空指针：成员 publisher_ 未初始化就使用；在构造函数中调用 shared_from_this()
  • 数组越界：访问 msg.ranges[i] 前没检查 size
  • 未捕获异常：tf2::TransformException、rclcpp::exceptions::ParameterNotDeclaredException
  • 多线程数据竞争：可用 -DCMAKE_CXX_FLAGS="-fsanitize=thread" 检测

11.4 rosbag2：录制与回放

rosbag2 把话题数据按时间戳原样保存下来，之后可以回放，就像机器人「重新经历」一遍。这是复现问题、离线开发算法、制作数据集的核心工具。

录制

/tf_static 一定要录

静态变换只在启动时发布一次（TRANSIENT_LOCAL）。如果录包开始时它已经发布过，ros2 bag record 会以兼容的 QoS 订阅并获取最后一条；但若录包遗漏了它，回放时传感器坐标系就全部缺失。

查看

回放

回放时不要同时运行产生相同话题的节点

例如回放包含 /tf 的 bag，同时又启动了 Gazebo 或驱动，两个来源的 TF 会冲突。回放场景下，只启动你要测试的算法节点，并设置 use_sim_time:=true。

11.6 诊断系统（diagnostics）

生产机器人需要持续监控各部件状态：电池、电机温度、传感器频率、CPU 负载等。ROS 的约定是各节点把状态发布到 /diagnostics（diagnostic_msgs/msg/DiagnosticArray），由聚合器汇总。

11.7 Foxglove

Foxglove 是现代化的机器人数据可视化工具，可以直接打开 MCAP 文件，也可以通过 WebSocket 连接实时系统，支持 3D、图表、图像、日志等多种面板组合，适合远程调试和团队共享。

11.8 系统化调试流程

  1. 节点在不在：ros2 node list
  2. 数据有没有：ros2 topic hz、ros2 topic echo --once
  3. 连接对不对：ros2 node info、ros2 topic info -v（QoS、发布 / 订阅数量）
  4. 坐标对不对：view_frames、tf2_echo、RViz
  5. 时间对不对：所有节点 use_sim_time 一致？时间戳是否合理？
  6. 参数对不对：ros2 param dump
  7. 日志说了什么：rqt_console 过滤 WARN 以上
  8. 能否复现：录包，离线回放，二分定位

自测题

1. 回放 bag 时 SLAM 节点报「extrapolation into the past」，最可能的原因？
SLAM 节点使用了系统时间（use_sim_time 为 false），而 bag 中消息时间戳是录制时的旧时间。应以 --clock 回放，并将 SLAM 节点的 use_sim_time 设为 true。
2. 录一段包含 1080p 相机的 bag，10 分钟后磁盘满了，该如何优化？
只录需要的话题；录压缩图像话题（/image_raw/compressed）而非原始图像；启用 zstd 压缩；用 --max-bag-size 分割并及时转移；或降低相机帧率 / 分辨率。
3. 节点在 launch 中启动时日志没有颜色，如何开启？
设置环境变量 RCUTILS_COLORIZED_OUTPUT=1。

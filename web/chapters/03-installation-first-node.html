3.7 理解 spin 与回调

ROS2 程序是事件驱动的。spin() 是一个循环，不断检查「有没有到期的定时器、有没有新消息、有没有服务请求」，有就调用对应的回调函数。

rclpy.spin(node)
   │
   ├─► 等待事件（定时器到期 / 消息到达 / 服务请求 …）
   ├─► 取出事件，调用对应回调 on_timer() / on_message()
   └─► 回到等待
不要在回调里写死循环或 time.sleep()

默认是单线程执行器：一个回调阻塞，所有其他回调（包括订阅）都会停止。周期性任务用定时器，耗时任务放到独立线程或使用多线程执行器（第 4 章）。

自测题

1. 运行 ros2 run my_first_nodes talker 报 “Package 'my_first_nodes' not found”，可能原因？
（1）当前终端没有 source ~/ros2_ws/install/setup.bash；（2）包没有构建成功；（3）在错误的目录执行了 colcon build（必须在工作空间根目录 ~/ros2_ws，而不是 src 里）。
2. 报 “No executable found”，又是什么原因？
包找到了但可执行程序没有。Python 包检查 setup.py 中 console_scripts 是否正确注册并重新构建；C++ 包检查 install(TARGETS ... DESTINATION lib/${PROJECT_NAME}) 是否写了。
3. 为什么 talker 和 listener 不需要知道对方的 IP 或进程号？
它们只约定话题名 chatter 和类型 std_msgs/msg/String，DDS 的发现机制会自动找到匹配的发布者与订阅者并建立连接。
4. 把 talker 的定时器回调改成 while True: publish(); time.sleep(1) 会怎样？
第一次进入回调后就永远不返回，spin 被卡死。看似能发布，但同一节点的其他回调（订阅、服务、参数服务）全部无法执行，Ctrl+C 也可能无法优雅退出。应使用定时器。

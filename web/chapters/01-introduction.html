第 1 章　为什么学 ROS / ROS2

搞清楚 ROS 解决什么问题、它由哪些部分组成、该选哪个发行版，以及 ROS1 与 ROS2 到底差在哪里。

阅读约 25 分钟无需编程

本章目标

  • 说清楚「机器人软件为什么需要一套中间件」
  • 理解 ROS 的四大组成：通信框架、工具、功能库、社区生态
  • 知道 Humble、Jazzy、Kilted、Rolling 等发行版的区别并做出选择

1.1 机器人软件的难题

假设你要做一台室内送餐机器人，它至少需要这些软件模块：

 ┌──────────┐   ┌──────────┐   ┌──────────┐
 │ 激光雷达 │   │  深度相机 │   │ 轮式编码器│      传感器驱动
 └────┬─────┘   └────┬─────┘   └────┬─────┘
      │ 点/扫描        │ 图像/点云     │ 轮速
      ▼               ▼              ▼
 ┌──────────────────────────────────────────┐
 │   定位（我在哪）  建图（环境长什么样）      │   感知与状态估计
 └───────────────────┬──────────────────────┘
                     ▼
 ┌──────────────────────────────────────────┐
 │   全局路径规划  →  局部避障控制             │   决策与规划
 └───────────────────┬──────────────────────┘
                     ▼  速度指令
 ┌──────────────────────────────────────────┐
 │        电机驱动 / 底盘控制器               │   执行
 └──────────────────────────────────────────┘

如果从零开发，你会遇到一连串工程问题：

  1. 进程间通信：模块之间怎么传数据？自己写 Socket 协议？数据格式怎么定义？
  2. 模块复用：别人写好的 SLAM 算法，接口和你的不一样，怎么接入？
  3. 时间与坐标：激光装在车头 20 cm 处，相机装在车顶，它们的数据怎么统一到同一个坐标系？时间戳怎么对齐？
  4. 调试：机器人跑一圈出了问题，怎么把当时的传感器数据录下来反复回放分析？
  5. 可视化：怎么把点云、路径、地图实时画出来？
  6. 多语言：算法同学用 Python，驱动同学用 C++，怎么协作？

ROS 的价值就是把这些「每个机器人项目都要重复解决的问题」统一解决掉，让你专注于算法和业务本身。

1.2 ROS 到底是什么

ROS 全称 Robot Operating System，但它不是 Windows、Linux 那种操作系统，它运行在 Linux（以及 Windows、macOS）之上。更准确的定义是：

定义

ROS 是一套面向机器人的开源软件开发框架，由「通信中间件 + 开发工具 + 功能库 + 社区生态」四部分组成。

组成部分内容举例
通信框架（Plumbing）节点之间的发布/订阅、请求/响应、长任务通信Topic、Service、Action、Parameter
工具（Tools）命令行、可视化、录包、构建系统ros2 CLI、RViz2、rqt、rosbag2、colcon
功能库（Capabilities）成熟的机器人算法包Nav2 导航、MoveIt 机械臂、slam_toolbox、ros2_control
生态（Ecosystem）数千个开源包、硬件厂商驱动、文档、社区激光雷达/相机厂商官方 ROS 驱动、ROS Discourse 论坛

一句话理解：ROS 之于机器人，类似 Spring 之于 Java 后端、React 之于前端——它规定了模块之间如何协作，并提供大量现成轮子。

1.4 发行版怎么选

ROS2 每年 5 月 23 日（世界海龟日）发布一个新版本，名字按字母顺序，以海龟品种命名。偶数年发布的是长期支持版（LTS），维护 5 年；奇数年是普通版，维护约 1.5 年。

发行版发布停止维护对应 Ubuntu配套 Gazebo建议
Jazzy Jalisco（LTS）2024-052029-0524.04Harmonic新手首选，本教材主线
Humble Hawksbill（LTS）2022-052027-0522.04Fortress（Classic 11 已 EOL）大量公司项目在用，资料最多
Kilted Kaiju2025-05约 2026 年底24.04Ionic短期版，不建议学习用
Rolling Ridley持续更新—最新最新给 ROS 本身的开发者用，API 会变
Noetic（ROS1）2020-052025-05（已停止）20.04Classic 11只用于维护老项目
选择建议

没有历史包袱就选 Jazzy + Ubuntu 24.04。公司项目还在 Humble 上也没关系：两者 API 差异很小，本教材的代码在 Humble 上基本都能直接运行，差异处会单独标注。

1.5 ROS1 与 ROS2 的核心差异

ROS1 诞生于学术研究，设计时假设「一台机器人、一台电脑、网络可靠」。当 ROS 被用到工业产品、无人车、多机器人系统时，这些假设不再成立，于是有了彻底重写的 ROS2。

维度ROS1ROS2带来的影响
节点发现依赖中心节点 roscore（Master）DDS 去中心化自动发现没有单点故障；不用先启动 roscore
通信协议自研 TCPROS / UDPROS工业标准 DDS（也支持 Zenoh）可调 QoS，可跨厂商互通
服务质量只有队列长度完整 QoS：可靠性、持久性、截止期等可适应无线等不可靠网络
实时性基本不支持设计上支持实时（需配合实时内核）可用于控制回路
节点生命周期无Lifecycle Node 状态机系统启动顺序可控
进程内通信Nodelet（较复杂）组件（Component）+ 零拷贝大数据（图像、点云）传输更高效
平台主要 LinuxLinux / Windows / macOS / 嵌入式（micro-ROS）可以跑在单片机上
安全无SROS2：加密、认证、访问控制可满足产品级安全需求
PythonPython 2/3（Noetic 才全面 3）Python 3—
构建工具catkinament + colcon命令完全不同
LaunchXMLPython / XML / YAML可在 launch 中写逻辑
ROS1 与 ROS2 不能直接互通

两者的消息无法直接互发。混合系统需要 ros1_bridge，而且 Noetic 已停止维护，新项目没有理由再选 ROS1。

1.6 三个核心概念（先有个印象）

后面所有章节都建立在下面三个概念上，现在不必完全理解：

节点（Node）

完成单一职责的程序单元，例如「激光雷达驱动节点」「路径规划节点」。一个可执行程序里可以有一个或多个节点。

通信接口

接口模式类比典型用途
Topic 话题发布 / 订阅，多对多，单向广播电台传感器数据流、速度指令
Service 服务请求 / 响应，一对一打电话问问题查询状态、触发一次性操作
Action 动作目标 + 持续反馈 + 结果，可取消点外卖并实时看配送进度导航到某点、机械臂抓取
Parameter 参数节点的可配置项软件的设置页最大速度、传感器频率

1.7 谁在用 ROS

  • 服务与物流机器人：仓储 AMR、送餐机器人、清洁机器人大量基于 Nav2
  • 工业机械臂：ABB、UR、FANUC、KUKA 都有官方或社区 ROS2 驱动，MoveIt 用于规划
  • 自动驾驶：Autoware 是基于 ROS2 的开源自动驾驶软件栈
  • 航天：NASA 的 VIPER 月球车、Astrobee 空间站机器人使用 ROS
  • 教育与科研：TurtleBot、各类机器人竞赛几乎都以 ROS 作为默认平台

1.8 学习 ROS 的正确姿势

  1. 先跑通，再理解：官方 demo 先跑起来，看到现象再去读原理。
  2. 善用命令行自省：ros2 node list、ros2 topic echo 是你观察系统的眼睛。
  3. 读官方文档而非过时博客：网上大量教程是 ROS1 或旧版 ROS2，命令和 API 已变化。注意看文章使用的发行版。
  4. 读源码：ROS 全部开源，遇到问题直接读 GitHub 上的源码往往最快。
  5. 做项目：第 16 章的毕业项目是检验你是否真正学会的标准。

测试视角

对测试工程师来说，本章最重要的两件事是：版本和约定。

关注点为什么重要测试中怎么做
发行版与依赖版本Humble 与 Jazzy 的默认行为不同（如 bag 默认格式、部分接口、Gazebo 版本），同一份代码在不同版本上结果可能不同测试报告和缺陷报告必须写明发行版；用 ros2 doctor --report 记录环境

单位与坐标约定（REP-103）米、秒、弧度；x 向前、y 向左、z 向上。单位或方向搞错是机器人最常见的缺陷之一边界用例中专门检查单位：例如角速度 1.0 是 1 rad/s（约 57°/s），不是 1°/s

自测题

1. ROS 是操作系统吗？它和 Ubuntu 是什么关系？
不是。ROS 是运行在操作系统之上的机器人软件框架（中间件 + 工具 + 功能库）。Ubuntu 是它最主要的宿主操作系统，ROS 通过 apt 软件源安装到 Ubuntu 中。
2. ROS1 的 roscore 挂掉会发生什么？ROS2 为什么没有这个问题？
ROS1 中所有节点通过 Master 互相发现。Master 挂掉后已建立的连接通常还能维持，但新节点无法加入、参数服务器不可用，系统无法恢复。ROS2 使用 DDS 的分布式发现协议，每个节点通过组播自动发现彼此，没有中心节点，因此不存在单点故障。
3. 让机器人「导航到厨房」应该用 Topic、Service 还是 Action？为什么？
用 Action。导航是耗时任务，需要持续反馈（剩余距离、当前位置），并且可能被中途取消。Service 会一直阻塞到完成，无法给出进度，也不能取消；Topic 没有「完成 / 失败」的结果语义。
4. 2026 年开始一个新项目，应选哪个发行版？
Jazzy（LTS，维护到 2029 年 5 月），配合 Ubuntu 24.04 和 Gazebo Harmonic。若必须与现有 Humble 系统集成，可以选 Humble，但要注意它在 2027 年 5 月停止维护。

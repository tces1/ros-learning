5.1 服务（Service）

  Client ── Request (mode=1) ──►  Server
  Client ◄── Response (success=True, message="...") ── Server
  • 一个服务名只能有一个服务端，可以有多个客户端
  • 适合快速完成的操作：查询、切换模式、触发一次计算
  • 服务端的处理函数应在毫秒级返回；需要几秒以上的操作请用 Action

5.2 参数（Parameter）

参数是节点的可配置项。ROS2 中每个节点持有自己的参数（不像 ROS1 有全局参数服务器），并且必须先声明后使用。

参数的设计原则
  • 会随部署环境变化的值（速度上限、话题名、设备端口、标定值）都应做成参数，不要写死。
  • 为参数写 description，ros2 param describe 与 rqt 都能看到，相当于自带文档。
  • 不允许运行时修改的参数可设置 read_only=True。

5.3 动作（Action）

动作用于耗时、需要中间反馈、可能被取消的任务。它的底层实际由 3 个服务 + 2 个话题组成：

  Action Client                                   Action Server
       │ ── send_goal（服务）──────────────────────► │  接受 / 拒绝目标
       │ ◄── feedback（话题）────────────────────── │  周期性反馈进度
       │ ◄── status（话题）──────────────────────── │  目标状态变化
       │ ── cancel_goal（服务）─────────────────────► │  请求取消
       │ ── get_result（服务）──────────────────────► │  获取最终结果

目标状态

一个目标会经历 ACCEPTED → EXECUTING → 终态（SUCCEEDED / CANCELED / ABORTED）。abort() 用于服务器自身判断任务失败（例如遇到障碍），canceled() 用于响应客户端的取消请求。

自测题

1. 两个节点都创建了名为 /set_mode 的服务端，会怎样？
ROS2 不会阻止，但客户端请求会发给哪一个是不确定的，属于设计错误。应保证一个服务名只有一个服务端。
2. ros2 param set /node speed 1.0 报 “Parameter not declared”，为什么？
节点没有调用 declare_parameter('speed', ...)。ROS2 默认不允许设置未声明的参数（除非创建节点时设置 allow_undeclared_parameters=True，一般不推荐）。
3. 动作服务器的 execute 回调里用 time.sleep，为什么需要多线程执行器？
execute 会长时间运行。若使用单线程执行器，执行期间无法处理取消请求、新目标或其他回调。多线程执行器配合可重入回调组，才能让取消请求在执行过程中被处理。
4. 动作底层由哪些服务和话题组成？
3 个服务：send_goal、cancel_goal、get_result；2 个话题：feedback、status。

第 7 章　TF2 坐标变换

机器人身上每个传感器、每个关节都有自己的坐标系。TF2 负责维护它们之间随时间变化的关系，让你能把任意数据从一个坐标系换算到另一个坐标系。

7.1 为什么需要 TF

激光雷达检测到前方 2 米处有障碍物，这个「2 米」是相对激光雷达本身的。要回答「障碍物在地图上的哪里」，需要依次知道：

   障碍物在 laser_link 中的坐标 (2.0, 0, 0)
        │  laser_link 相对 base_link：前方 0.15 m、高 0.2 m（固定安装）
        ▼
   障碍物在 base_link 中的坐标 (2.15, 0, 0.2)
        │  base_link 相对 odom：由轮式里程计实时计算
        ▼
   障碍物在 odom 中的坐标
        │  odom 相对 map：由定位算法（AMCL / SLAM）修正
        ▼
   障碍物在 map 中的坐标  ← 规划器需要的

TF2 把这些变换组织成一棵树，并且带时间戳缓存（默认 10 秒），你只需要问「t 时刻 A 坐标系中的点在 B 坐标系中是多少」。

  map ──► odom ──► base_footprint ──► base_link ──┬──► laser_link
   │        │                                     ├──► imu_link
   │        │                                     ├──► camera_link ──► camera_optical_frame
   │        │                                     ├──► left_wheel_link
   │        │                                     └──► right_wheel_link
   │        └─ 由里程计 / EKF 发布：连续平滑，但会随时间漂移
   └─ 由定位算法发布：修正漂移，可能发生跳变
坐标系含义谁发布到它的变换特点
map世界固定坐标系—（树根）长期准确，可能跳变
odom里程计坐标系定位节点发布 map→odom短期准确连续，长期漂移
base_footprint机器人在地面上的投影里程计 / EKF 发布 odom→base_footprintz=0，2D 导航常用
base_link机器人本体中心robot_state_publisher（URDF 固定关节）刚性连接于本体
传感器坐标系激光、相机、IMUrobot_state_publisher来自 URDF 的安装位置
为什么不直接发布 map→base_link？

TF 树要求每个坐标系只能有一个父节点。定位算法输出 map→base_link 的位姿，但它会把 它算出的 map→base_link 减去当前的 odom→base_link，得到 map→odom 再发布。这样里程计保持连续（局部控制器平滑），定位修正以「整体平移 odom」的方式体现。

7.3 姿态表示：欧拉角与四元数

ROS 消息中姿态统一用四元数 (x, y, z, w) 表示，因为它没有万向节锁、插值平滑、计算高效。但人更容易理解欧拉角（roll 绕 x、pitch 绕 y、yaw 绕 z）。

描述欧拉角 (roll, pitch, yaw)四元数 (x, y, z, w)
无旋转(0, 0, 0)(0, 0, 0, 1)
原地左转 90°(0, 0, π/2)(0, 0, 0.7071, 0.7071)
掉头 180°(0, 0, π)(0, 0, 1, 0)
右转 90°(0, 0, −π/2)(0, 0, −0.7071, 0.7071)
四元数必须归一化

全 0 的四元数 (0, 0, 0, 0) 是非法的——这是新手手写 Pose 时最常见的错误，会让 TF / Nav2 报错或行为异常。不旋转时一定要写 w = 1.0。

常见错误信息：

  • “Lookup would require extrapolation into the future”：请求的时刻比最新变换还新。通常是 TF 发布频率低、网络延迟，或某些节点用仿真时间而其他用系统时间。可加 timeout 等待。
  • “extrapolation into the past”：请求的时刻早于缓存中最旧的数据（默认缓存 10 秒），或时间源不一致。
  • “frame does not exist”：坐标系从未被发布，或名字拼错（注意不要以 / 开头，ROS2 中 frame_id 写作 base_link 而非 /base_link）。
  • “not part of the same tree”：两个坐标系之间没有连通路径，TF 树断开了。

自测题

1. 一个坐标系能有两个父坐标系吗？如果 AMCL 和 EKF 都发布 odom→base_link 会怎样？
不能，TF 必须是树。两个节点发布同一对坐标系的变换会导致数据交替跳变、定位抖动。正确做法：EKF 发布 odom→base_link，AMCL 发布 map→odom。
2. lookup_transform('map', 'laser_link', t) 返回的平移量表示什么？
laser_link 坐标系原点在 map 坐标系中的位置（以及其姿态）。用这个变换可以把 laser_link 中的数据转换到 map 中。
3. 机器人朝向 yaw = 90°，对应的四元数是多少？
(x, y, z, w) = (0, 0, sin(45°), cos(45°)) ≈ (0, 0, 0.7071, 0.7071)。
4. 相机图像中检测到的物体，为什么要变换到 base_link 时要用 camera_optical_frame 而不是 camera_link？
图像像素与深度计算出的 3D 坐标遵循光学约定（z 前、x 右、y 下），属于 optical frame；camera_link 遵循机器人约定（x 前、y 左、z 上）。两者之间有一个固定旋转，用错会导致坐标轴混乱。

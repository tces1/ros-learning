8.1 URDF 是什么

URDF（Unified Robot Description Format）是一个 XML 文件，把机器人描述为由关节（joint）连接的连杆（link）组成的树。

            base_footprint
                 │ (fixed)
             base_link ────────────────┬──────────────┬──────────────┐
                 │ (continuous)        │ (continuous) │ (fixed)      │ (fixed)
          left_wheel_link     right_wheel_link   caster_link    laser_link

谁会用到 URDF：

  • robot_state_publisher：根据 URDF 和关节角度计算并发布所有 link 的 TF
  • RViz：显示机器人外观
  • Gazebo：物理仿真（需要碰撞和惯性）
  • MoveIt：碰撞检测与运动学
  • ros2_control：读取硬件接口声明（第 12 章）

8.2 Link 的三种属性

属性作用建议
<visual>显示外观（RViz、Gazebo 画面）可用精细的 mesh（STL / DAE）
<collision>碰撞检测与物理接触用简单几何体（box、cylinder、sphere），计算快
<inertial>质量与惯性张量仿真必须有且合理，否则模型乱飞

8.3 Joint 关节类型

类型自由度例子需要 limit
fixed0传感器安装、base_footprint否
continuous绕轴无限旋转车轮否
revolute绕轴有限旋转机械臂关节、舵机是
prismatic沿轴平移升降台、直线导轨、夹爪手指是
floating6很少使用否
planar平面内 3很少使用否
两个 origin 别混淆

joint 的 origin 决定子 link 坐标系放在哪里；link 内 visual 的 origin 决定几何体相对自身坐标系的偏移。先放坐标系，再放形状。

8.4 Xacro：让 URDF 可维护

纯 URDF 里两个轮子要写两遍几乎相同的代码，改个轮径要改十几处。Xacro（XML Macros）提供：

  • <xacro:property>：定义常量
  • ${...}：数学表达式，如 ${wheel_radius * 2}、${pi/2}
  • <xacro:macro>：可复用的模板
  • <xacro:include>：拆分文件
  • <xacro:arg> 与 $(arg ...)：从外部传参
  • <xacro:if value="...">：条件

数据流

joint_state_publisher 发布 /joint_states（可动关节的角度）→ robot_state_publisher 结合 URDF 计算每个 link 的位姿 → 发布到 /tf（可动关节）与 /tf_static（固定关节）。真实机器人或仿真中，/joint_states 由驱动或 Gazebo 提供，就不需要 joint_state_publisher 了。

8.6 检查与调试

现象原因
RViz 中 RobotModel 报 “No transform from [xxx]”可动关节没有 /joint_states，忘了启动 joint_state_publisher

8.7 从 CAD 导出

复杂机器人通常从 CAD 导出 URDF：SolidWorks 有 sw_urdf_exporter 插件，Onshape 可用 onshape-to-robot，Fusion 360 有社区导出脚本。导出后仍建议手动检查坐标系方向（REP-103）、简化碰撞体、核对质量。

测试视角

URDF 是仿真、TF、碰撞检测、运动规划的共同来源。它错了，后面所有测试的基础都是错的。

检查项方法后果
能否正确展开和解析xacro + check_urdf，放进 CI启动失败
惯性参数合理质量 > 0，惯性矩阵正定、量级合理Gazebo 中机器人抖动、飞起、穿地
碰撞几何与外形一致RViz 中同时显示 visual 和 collision规划认为能通过，实际擦碰
传感器安装位姿与实物测量对比仿真测试结论不适用于实机（见 T4.1）
关节限位与电机、机械限位对比规划出超出硬件能力的动作
模型与实物要「对账」

实机测试前，用卷尺测量雷达高度、轮距、轮径，与 URDF 对比并记录。仿真中通过、实机失败的问题，很多源于模型与实物不一致（例如低矮障碍物在雷达扫描平面以下，见 T7 自测题）。

自测题

1. 为什么要单独有一个 base_footprint？
它是机器人在地面上的投影（z=0），2D 导航只关心平面位姿，用 base_footprint 作为机器人基准可以避免 base_link 高度带来的偏差。base_link 通常位于本体中心或轮轴高度。
2. collision 可以直接复制 visual 中精细的 mesh 吗？
可以，但不推荐。精细 mesh 的碰撞检测计算量大，会拖慢仿真和 MoveIt 规划。应使用简化的基本几何体或简化后的凸包 mesh。
3. 把轮距从 0.35 改为 0.40，需要改几处？
只需改 wheel_separation 属性一处，两个车轮的位置都通过表达式 ${y_reflect * wheel_separation / 2} 计算。这就是 Xacro 的价值。

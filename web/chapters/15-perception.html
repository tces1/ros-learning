为什么用 NumPy

360 个点用 Python 循环也能处理，但对 3D 激光（数万点）就太慢了。用 NumPy 向量化运算是 Python 处理传感器数据的基本功。Nav2 自带的 collision_monitor 是这个思路的工业级实现。

15.3 相机模型与标定

针孔模型

  3D 点 (X, Y, Z)（相机光学坐标系：z 向前、x 向右、y 向下）
        │  投影
        ▼
  u = fx · X / Z + cx          fx, fy：焦距（像素）
  v = fy · Y / Z + cy          cx, cy：主点（通常接近图像中心）

  反过来，已知像素 (u, v) 和深度 Z：
  X = (u − cx) · Z / fx
  Y = (v − cy) · Z / fy

这些内参保存在 sensor_msgs/msg/CameraInfo 的 k 矩阵中：k = [fx, 0, cx, 0, fy, cy, 0, 0, 1]。d 是畸变系数。

15.6 接入深度学习模型

推荐模式：一个节点订阅图像，运行模型，发布标准的 vision_msgs/msg/Detection2DArray，下游节点（跟踪、抓取、导航）只依赖这个消息类型，与具体模型解耦。

推理耗时会阻塞回调

模型推理可能需要几十毫秒，订阅使用 depth=1 的传感器 QoS 处理最新帧即可，避免排队处理过期图像。需要更高性能时考虑 C++ + TensorRT / OpenVINO，或 NVIDIA Isaac ROS。

自测题

1. LaserScan 中 ranges 有 inf 值代表什么？如何处理？
通常表示该方向在量程内没有回波（前方空旷或超出最大距离），有的驱动也用 inf / nan 表示无效测量。计算最近障碍物时应过滤掉非有限值和超出 [range_min, range_max] 的值。
2. fx = 600、cx = 320，像素 u = 420，深度 2 m，该点 X 坐标是多少？在哪个坐标系？
X = (420 − 320) × 2 / 600 ≈ 0.333 m，位于 camera_optical_frame（x 向右），即光轴右侧约 33 cm。
3. 为什么检测结果的 header 要沿用原始图像的 header？
时间戳表示图像采集时刻，下游需要用它查询当时的 TF（机器人可能已移动）；frame_id 说明坐标属于哪个相机。用处理完成时刻作为时间戳会导致坐标变换误差。

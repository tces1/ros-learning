第 14 章　MoveIt 2 机械臂运动规划

MoveIt 是 ROS 中机械臂运动规划的标准框架。本章用官方 Panda 机械臂演示交互式规划，然后用 C++ 编写程序：移动到目标位姿、添加障碍物、规划笛卡尔直线路径，最后介绍如何为自己的机械臂生成配置。

动手约 3–4 小时机械臂方向

本章目标

  • 理解运动学、运动规划、碰撞检测、轨迹执行的完整链路
  • 在 RViz 中交互式规划和执行
  • 用 MoveGroupInterface 编程实现位姿目标、关节目标、笛卡尔路径
  • 用 PlanningSceneInterface 添加碰撞物体
  • 用 Setup Assistant 为自定义机械臂生成配置包

14.1 机械臂规划要解决的问题

   目标：「把末端移动到桌面上方 10 cm、朝下」
        │
        ▼  逆运动学（IK）：末端位姿 → 各关节角度（可能有多解或无解）
        ▼  运动规划：从当前关节角到目标关节角，找到一条不碰撞的路径
        ▼  时间参数化：给路径加上速度、加速度，使其满足关节限位
        ▼  执行：通过 FollowJointTrajectory 动作发送给控制器（第 12 章）
   机械臂运动
概念解释
正运动学（FK）已知关节角，求末端位姿。唯一解，计算简单
逆运动学（IK）已知末端位姿，求关节角。可能多解 / 无解。MoveIt 默认用 KDL 数值解，可换 TRAC-IK、pick_ik 或解析解 IKFast
规划组（Planning Group）一组一起规划的关节，如 panda_arm（7 关节）、hand（夹爪）
末端执行器（End Effector）夹爪、吸盘等，挂在规划组末端
规划场景（Planning Scene）机器人当前状态 + 环境中的碰撞物体
ACM（允许碰撞矩阵）哪些 link 之间的接触不算碰撞（如相邻连杆）

14.3 安装与演示

RViz 打开后：

  1. 在 MotionPlanning 面板的 Planning 标签中，Planning Group 选 panda_arm
  2. 拖动末端的交互标记（彩色箭头和圆环）到新位置，橙色的「目标机器人」会跟随
  3. 点 Plan，观察规划出的轨迹动画；点 Execute 执行
  4. 在 Scene Objects 标签中可以添加方块，再次规划时机械臂会绕开它
  5. 在 Context 标签中切换规划器（如 OMPL 的 RRTConnect、Pilz 的 LIN 直线运动）
demo.launch.py 使用模拟硬件

演示使用 ros2_control 的 mock_components，所以「执行」只是在 RViz 中更新状态。换成 Gazebo 或真实机械臂时，只需替换硬件插件，MoveIt 侧不变。

14.4 规划器选择

规划器特点适用
OMPL（RRTConnect 等）基于采样，快速找到可行路径，但路径可能绕远、每次结果不同默认，复杂环境避障
Pilz Industrial Motion确定性的 PTP / LIN / CIRC 运动工业场景：直线插补、圆弧、可预测的运动
CHOMP / STOMP基于优化，路径平滑对轨迹质量要求高的场景

14.7 为自己的机械臂生成配置

步骤内容
1. 加载 URDF选择你机械臂的 URDF / xacro
2. Self-Collisions自动采样生成 ACM（禁用永远不会碰撞或相邻的 link 对）
3. Virtual Joints机械臂底座固定在世界上时添加 world → base_link 固定虚关节
4. Planning Groups定义 arm（关节链）和 gripper 组，并选择运动学求解器
5. Robot Poses定义命名位姿如 home、ready
6. End Effectors指定夹爪组及其父 link
7. ros2_control / Controllers生成 joint_trajectory_controller 配置
8. Generate输出 xxx_moveit_config 包

14.8 MoveIt Servo：实时遥操作

规划 + 执行是「先想好再动」。如果需要用手柄、视觉伺服实时控制末端速度，使用 MoveIt Servo：它接收末端速度指令（TwistStamped）或关节速度，实时计算关节指令，并持续做奇异点与碰撞检查。

14.9 常见问题

现象原因与处理
“No IK solution”目标超出工作空间、姿态不可达；尝试放宽姿态、换 IK 求解器、增加 IK 超时
规划成功但执行失败控制器未激活或名称不匹配（moveit_controllers.yaml）；轨迹起点与当前状态偏差过大
笛卡尔路径完成度很低路径途经奇异点、关节限位或碰撞；减小步长或调整路径
程序卡在 getCurrentPose节点没有 spin，收不到 /joint_states
机械臂绕大圈OMPL 随机性导致；增加规划时间与尝试次数、使用 Pilz PTP、或加路径约束

测试视角

机械臂测试的方法与移动机器人相同：在仿真中批量运行、统计结果，再在实机上验证。差别在于指标：

维度指标 / 检查
规划规划成功率、规划耗时（p95）、轨迹长度与执行时间；同一请求多次规划结果的差异（采样规划器具有随机性）
笛卡尔路径computeCartesianPath 返回的完成比例（fraction），小于 1 时上层是否正确处理
碰撞规划场景中的障碍是否与实物一致；靠近障碍的目标是否被正确拒绝
边界工作空间边缘、奇异位形附近、关节限位附近的目标
重复定位精度多次到达同一位姿的偏差（实机，用标定工具测量）
安全速度 / 加速度缩放生效；急停后轨迹中止；协作场景的力与速度限制（ISO/TS 15066）
把本章的 move_demo 变成测试

准备一组目标位姿（包括若干「应该失败」的：不可达、与障碍碰撞），循环调用 plan()，记录每次的成功与耗时，输出成功率和耗时分布。思路与 T4 的场景执行器完全相同。

自测题

1. 为什么逆运动学可能有多个解？
对于 6 自由度及以上的机械臂，同一个末端位姿可以由不同的关节配置实现（如「肘部朝上」与「肘部朝下」）。7 自由度机械臂（如 Panda）还有冗余自由度，存在无穷多解。
2. 什么时候选 Pilz 的 LIN 而不是 OMPL？
需要末端严格走直线时（如焊接、涂胶、插入孔），或需要每次运动完全可预测时。OMPL 只保证无碰撞，不保证末端路径形状。
3. 为什么抓取后要 attachObject？
否则 MoveIt 认为物体仍留在原地：一方面夹爪与物体的接触会被判为碰撞导致规划失败；另一方面移动过程中被抓物体与环境的碰撞不会被检查。

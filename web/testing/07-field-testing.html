T7　实机与现场测试

自动化测试再完善，机器人最终要在真实世界里工作。实机与现场测试的难点不在写代码，而在于：安全地组织测试、设计有代表性的用例、在有限的测试时间里收集到足够的数据，并把现场现象转化为开发能处理的缺陷报告。

阅读约 2.5 小时测试篇前置：T1、T5、T6

本篇目标

  • 掌握实机测试的安全规程，能制定测试前检查清单
  • 了解 HIL 台架测试的目的和典型检查项
  • 能写出一份实机测试计划
  • 用环境矩阵、边界值、状态迁移、错误推测等方法设计机器人测试用例
  • 写出开发能直接处理的缺陷报告
  • 用统计方法确定测试次数、报告可靠性指标

T7.2 安全第一

实机测试的第一条规则

任何新版本、新参数、新场地的实机测试，第一个用例永远是验证急停。急停不可靠时，不执行任何其他测试。

角色分工

角色职责
测试负责人按计划执行用例，判定结果，决定是否继续
安全员手持急停，全程只关注机器人与人员安全，有权随时叫停（不兼任其他工作）
记录员记录时间、现象、用例编号，拍摄视频，确认录包在运行

测试前检查清单

  • 测试区域已清场、设置围挡或警示，无关人员已离开
  • 硬件急停按钮按下后，电机断电或停止，且松开后不会自动恢复运动
  • 遥控 / 软件急停有效，并测过响应距离
  • 测试初期最大速度已调低（如设计值的 50%），并通过参数确认生效
  • 底盘指令超时已验证（停止发送指令后机器人在规定时间内停下）
  • 电池电量充足，记录了开始电量
  • 软件版本（git SHA）、参数文件、地图版本已记录
  • 录包已启动，确认关键话题都在录制（ros2 bag info 或录制日志）
  • 视频拍摄设备时间已与机器人时间对齐（拍一下显示机器人时间的屏幕）
  • 所有人知道「停止」口令和撤离路线

相关标准

不同类型的机器人适用不同的安全标准，测试工程师至少要知道自己产品对应哪些标准，以及其中要求验证的项目：

标准适用范围
ISO 3691-4无人驾驶工业车辆（AGV / AMR）
ISO 13482个人护理机器人（服务、陪护、移动辅助）
ISO 10218-1/-2工业机器人及其集成
ISO/TS 15066协作机器人（人机协作的力与速度限制）
IEC 61508 / ISO 13849功能安全、安全相关控制系统

具体适用的标准与认证要求以产品所在行业和地区的法规为准。

T7.3 HIL 台架测试

台架上，机器人的车轮架空（或电机连接到负载台），真实的工控机、驱动板、传感器都在工作，但机器人不会真的移动。这是第一次接触真实硬件时最安全的测试方式。

检查项方法期望
运动方向发送 linear.x = 0.1两轮向「前」转；/odom 的 x 增加
转向方向发送 angular.z = 0.5左轮后转、右轮前转（逆时针）；/odom 的 yaw 增加
速度标定发送固定速度 10 s，数车轮圈数里程计距离与实际圈数 × 周长误差 < 2%
指令超时持续发送后停止发送在设计超时（如 0.5 s）内停转
急停链路运行中按下急停立即停转；松开后不自动恢复；软件收到急停状态
限速发送超过上限的速度实际速度被限制在上限内
通信中断拔掉驱动板的串口 / CAN 线驱动报错、诊断变为 ERROR、电机停止；重新连接后可恢复
传感器遮挡雷达、拔掉雷达频率、诊断、安全逻辑按设计反应
方向与符号错误是新硬件最常见的缺陷

电机接线反了、编码器方向反了、IMU 坐标系与 REP-103 不一致，都会导致「仿真里好好的，实机一跑就乱转」。台架上用小速度逐个验证方向和符号，比在场地里排查快得多，也安全得多。

T7.5 用例设计方法

环境矩阵与组合测试

机器人的行为受多个环境因素影响。列出因素和取值，形成环境矩阵：

因素取值
地面瓷砖、地毯、门槛（2 cm）、坡道（5°）
光照正常、窗边强光、关灯
障碍物无、静态箱子、行人、低矮物体（10 cm）、玻璃门、黑色家具
通道宽度2 m、1 m、0.7 m、0.6 m
电量满电、20%、低于返航阈值
网络良好、弱信号、断开

全组合是 4 × 3 × 6 × 4 × 3 × 3 = 2592 种，不可能全部测试。成对组合测试（pairwise）保证任意两个因素的每对取值至少出现一次，通常只需要几十个用例，就能发现大部分由两个因素共同引起的问题。可以用 Python 库 allpairspy 或 PICT 等工具生成组合，再人工补充高风险组合（如「玻璃门 + 强光」）。

边界值

对象边界示例为什么容易出问题
通道宽度机器人宽度 + 2 × 膨胀半径 附近 ±5 cm代价地图膨胀导致「看起来能过却规划失败」或「擦边通过」
障碍物高度雷达扫描平面高度上下（如 18 cm、22 cm）低于扫描平面的障碍对 2D 雷达不可见
坡度 / 门槛设计上限及略高于上限打滑导致里程计误差、定位丢失
速度最大速度、最小可控速度高速时制动距离、低速时电机死区
电量返航阈值附近阈值判断的 < 与 ≤、返航途中电量耗尽
目标位置离墙恰好等于膨胀半径、地图边缘目标在代价地图致命区内被拒绝

T7.6 执行与记录

现场记录的三个习惯

1）记时间：每个现象精确到分钟，开发拿到 bag 后能直接定位。2）记次数：「10 次中第 4 次出现」比「偶尔出现」有用得多。3）先保存数据再处理：出现异常时先确认 bag 已保存（或触发快照），再尝试恢复机器人。

严重程度

级别定义示例
S1 致命可能造成人身伤害或设备损坏；安全功能失效急停失效、碰撞行人、失控运动
S2 严重主要功能失败，无法自动恢复，需要人工干预定位丢失后不再恢复、巡逻卡死
S3 一般功能受影响但可自动恢复，或性能不达标绕行时停顿 8 s、到点误差偏大
S4 轻微体验、显示、日志问题状态消息文字错误

模板

「机器人有时候会撞」不是缺陷报告

开发拿到报告后应该能回答：哪个版本、什么条件、多大概率、数据在哪、期望是什么。缺任何一项，都会多一轮沟通。在机器人项目中，没有 bag 的缺陷报告基本无法处理。

T7.8 统计：要测多少次？

如果连续 n 次测试都没有失败，能有多大把握说成功率 ≥ p？若要以置信度 C 断言成功率 ≥ p，需要的无失败测试次数为：

n ≥ ln(1 − C) / ln(p)        例：C = 95%，p = 95%  →  n ≥ ln(0.05) / ln(0.95) ≈ 58.4，取 59 次
目标成功率 p置信度 90%置信度 95%
90%22 次29 次
95%45 次59 次
99%230 次299 次

结论很直接：用实机测试证明高可靠性非常昂贵。这也说明了为什么要在仿真和回放中做大量统计测试，实机测试则集中在仿真无法覆盖的方面。

可靠性指标的计算

指标计算示例
任务成功率成功任务数 / 总任务数58 / 60 = 96.7%
MDBF总行驶里程 / 故障次数12.6 km / 3 = 4.2 km
人工干预率人工干预次数 / 运行小时数2 次 / 4 h = 0.5 次/h

故障次数为 0 时，不要报告「MDBF 无穷大」，而是按上面的方法给出置信下限，例如「行驶 12.6 km 无故障，95% 置信下 MDBF ≥ 12.6 / 3 = 4.2 km」（三分之一规则：0 次失败时，95% 置信下的故障率上限约为 3 / n）。

T7.9 测试报告与发布决策

测试报告的读者是需要做发布决策的人，结论放在最前面：

  1. 结论：建议发布 / 有条件发布 / 不建议发布，一句话说明理由
  2. 准出条件对照：每一条准出条件是否满足，附数据
  3. 遗留缺陷与风险：未关闭缺陷列表、影响范围、规避措施
  4. 测试覆盖：执行了哪些用例，哪些因故未执行
  5. 详细数据：各用例结果、指标、bag 与视频索引

自测题

1. 为什么安全员不能同时兼任记录员？
安全员的唯一任务是在危险出现的瞬间按下急停。一旦分心看屏幕或记笔记，反应时间就会大幅增加。机器人可能在一两秒内移动一米以上。
2. 低矮障碍物（10 cm 高的箱子）在仿真中能被检测到，实机却撞上了，可能是什么原因？
2D 雷达只能看到扫描平面高度上的物体。如果实机雷达安装高度为 20 cm，10 cm 的箱子就在扫描平面以下；仿真模型中的雷达高度或障碍物尺寸可能与实机不一致。这是边界值用例（障碍物高度 vs 扫描平面高度）要覆盖的问题，也是仿真与现实差距的典型例子。
3. 实机测试 20 次全部成功，能否声称成功率 ≥ 95%？
不能。20 次无失败时，95% 置信下的成功率下限约为 86%（按三分之一规则，失败率上限约 3/20 = 15%）。要以 95% 置信度声称 ≥ 95%，需要约 59 次无失败测试。
4. 一份好的机器人缺陷报告必须包含哪些信息？
版本（git SHA、参数、地图）、环境与前置条件、复现步骤、期望与实际结果（最好量化）、复现率、bag 路径及问题时间点、视频或截图、严重程度。

单元测试（L0）组件测试（L1）
被测对象纯函数、纯类一个 ROS 节点（或一个类 + 它的 ROS 外壳）
需要 rclpy.init()不需要需要
通信无无，或仅在同一进程内

C++

覆盖率只是下限

100% 行覆盖率的 clamp 依然有 NaN 缺陷。覆盖率告诉你「哪些代码完全没被测过」，不能告诉你「测过的代码是否正确」。在机器人项目中，安全相关模块（急停、限速、碰撞检测）应追求更高的分支覆盖率，并配合性质测试与边界值测试。

T2.7 用例命名与组织

  • 用例名描述「条件 + 期望」：test_obstacle_ahead_blocks_forward 比 test_safety_1 好得多，失败时一眼就知道哪里出了问题
  • 一个用例只验证一个行为；断言失败信息写清楚实际值（如上面 f'clamp(nan, {limit}) 返回了 {out}'）
  • 测试文件与被测模块一一对应：safety_stop.py ↔ test_safety_stop.py
  • 每个缺陷修复都附带一个回归用例，用例名或注释中写缺陷编号
  • 用 pytest -m "not slow" 这类标记把慢用例与快用例分开，提交时只跑快的

自测题

1. 为什么 clamp(nan, 1.0) 会返回 1.0？
与 NaN 的任何比较结果都是 False。min(1.0, nan) 先取 1.0 作为当前最小值，再比较 nan < 1.0 为 False，于是保留 1.0；max(-1.0, 1.0) 返回 1.0。结果是无效输入变成了满速输出。
2. 「失效时放行」和「失效时安全」分别是什么意思？
失效时放行（fail-open）：依赖的数据或组件失效时，系统按「一切正常」处理，例如没有雷达数据时放行前进。失效时安全（fail-safe）：失效时进入安全状态，例如雷达超时就禁止前进。安全相关功能必须是后者。
3. 直接调用回调的组件测试和走真实通信的组件测试，各自能发现什么问题？
直接调用回调：速度快、确定性高，能发现逻辑、状态机、参数处理问题。走真实通信：能发现服务 / 话题名、类型、QoS、注册方式等「接线」问题。两者互补，前者数量多，后者少量覆盖关键接口即可。
4. xfail(strict=True) 的作用是什么？
把已知缺陷的用例标记为「预期失败」，CI 不会因此变红；strict=True 时如果用例意外通过（缺陷被修复），测试会报失败，提醒移除标记，把它变成正式的回归测试。

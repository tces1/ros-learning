# 第 1 章：为什么学 ROS / ROS2

## 1.1 机器人软件为何需要「操作系统」

现代机器人通常包含：

- 多个传感器（相机、激光雷达、IMU）
- 多个执行器（轮式底盘、机械臂、夹爪）
- 多个算法模块（定位、建图、规划、控制）

若每个模块用 ad-hoc 的 Socket / 自定义协议互联，会出现：

- 接口不统一，换传感器就要改一大片代码
- 难以复用社区算法（SLAM、导航栈）
- 多进程、多机协同难以标准化

**ROS（Robot Operating System）** 不是传统意义上的内核，而是一套 **中间件 + 工具链 + 生态约定**：用统一的通信模型把「节点」连接起来，并提供命令行、可视化、录包、参数等企业级能力。

## 1.2 ROS1 与 ROS2 的定位

| 维度 | ROS1（如 Noetic） | ROS2（如 Humble/Jazzy） |
|------|-------------------|-------------------------|
| 底层中间件 | 自研 TCPROS/UDPROS | DDS（可插拔 RMW） |
| 实时性 / 嵌入式 | 较弱 | 设计目标包含实时与嵌入式 |
| 多机器人 / 发现 | 依赖 Master（单点） | 去中心化发现（可配置域） |
| 生命周期 | 无统一生命周期节点 | 有 Lifecycle Node |
| 安全 | 社区方案为主 | DDS 安全插件（可选） |
| 维护状态 | Noetic 已 EOL 方向 | 主流新项目首选 |

**学习建议**：新项目直接 ROS2；维护老仓库或读老论文时再补 ROS1。

## 1.3 核心心智模型（先记住这三句话）

1. **一切皆节点（Node）**：一个可执行进程，完成一项职责（如读激光、发速度指令）。
2. **节点之间用接口通信**：话题（Topic，异步流）、服务（Service，请求/响应）、动作（Action，带反馈的长任务）。
3. **数据有类型（message / srv / action）**：在 `.msg` / `.srv` / `.action` 中定义，强类型、可版本化。

## 1.4 你将学会什么

学完本教材，你应能：

- 用 `colcon` 构建工作空间，编写 C++ 或 Python 节点
- 设计话题/服务接口，用 Launch 启动多节点系统
- 使用 TF2 表达坐标系，用 URDF 描述机器人模型
- 在仿真中跑通「传感器 → 感知/导航」最小闭环
- 知道如何查官方文档、读开源包源码

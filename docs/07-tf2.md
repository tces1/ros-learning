# 第 7 章：TF2 与坐标系

## 7.1 为什么需要 TF

传感器数据、运动学、导航都在不同 **坐标系（frame）** 下表达。TF2 维护 **坐标树（tree）**：

- 每个时刻知道 `map → odom → base_link → laser_link` 等变换
- 算法可把点云从 `laser_link` 变换到 `base_link` 或 `map`

**规则**：树必须是连通的、无环；由多个 **广播者（broadcaster）** 发布变换。

## 7.2 常见 frame 约定（REP-105）

| Frame | 含义 |
|-------|------|
| `map` | 全局地图坐标，可能跳变（定位校正） |
| `odom` | 里程计，连续但会漂移 |
| `base_link` | 机器人底盘 |
| `laser_link` / `camera_link` | 传感器外参 |

`map → odom` 通常由定位节点发布；`odom → base_link` 由轮速里程计或融合滤波发布。

## 7.3 工具

```bash
ros2 run tf2_tools view_frames   # 生成 frames.pdf 图
ros2 run tf2_ros tf2_echo map base_link
```

RViz2：Fixed Frame 设为 `map` 或 `odom`，查看 TF 是否断裂（红字）。

## 7.4 在代码里查询变换

```python
from tf2_ros import Buffer, TransformListener

buffer = Buffer()
listener = TransformListener(buffer, node)
transform = buffer.lookup_transform('target', 'source', rclpy.time.Time())
```

使用 `tf2_geometry_msgs` 对 `PoseStamped` / 点云做变换。

## 7.5 静态 TF

传感器相对底盘不变 → `static_transform_publisher` 或 URDF 中的 fixed joint。

```bash
ros2 run tf2_ros static_transform_publisher 0 0 0.2 0 0 0 base_link laser_link
```

## 7.6 ROS1 对照

`tf` → `tf2`；ROS1 的 `/tf` 话题在 ROS2 仍为 `/tf` 与 `/tf_static`。
